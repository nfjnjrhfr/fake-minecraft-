# 連線節點建議（網頁版）

一個可以在 **Safari 直接開、免登入、可加到主畫面**的單頁工具。
它量測你當下的網速與到各國的延遲，然後算出應該連哪一國的節點，
並產生對應的 pyvpn 客戶端設定。

## 它做什麼、不做什麼

| | |
|---|---|
| ✅ 量測對外 IP、出口國家、最近的 CDN 節點 | 透過 `speed.cloudflare.com/cdn-cgi/trace` |
| ✅ 量測真實下載速度 | 實際下載 2–20 MB 並計時 |
| ✅ 量測到 10 個國家的延遲 | 對各地區實體機房的端點計時，非 anycast |
| ✅ 依網速判斷可接受哪些國家 | 速度越慢，可容忍的延遲差距越小 |
| ✅ 產生 pyvpn 設定 | 一鍵複製 |
| ❌ **建立 VPN 連線** | 網頁做不到，見下方 |

### 為什麼網頁不能自己連 VPN

iOS 只允許取得 **NetworkExtension** 權限的原生 App 接管系統流量。
Safari 沒有這個 API，也沒有任何 JavaScript 介面可以建立隧道或改路由。
所以任何宣稱「在瀏覽器裡開 VPN」的網頁都做不到——它們實際上多半只是
把某個網站的內容轉一手的網頁代理，跟 VPN 不是同一件事。

實際的連線由本專案的 `pyvpn` 客戶端負責。

## 部署到 GitHub Pages（免登入的公開網址）

1. 這個資料夾已經叫 `docs/`，GitHub Pages 認得這個名字。
2. GitHub → **Settings** → **Pages**
3. **Source** 選 `Deploy from a branch`
4. **Branch** 選 `main`（或這個分支），資料夾選 **`/docs`**，按 Save
5. 一兩分鐘後網址會長這樣：

   ```
   https://<你的帳號>.github.io/<repo 名稱>/
   ```

這個網址是公開的、**不需要登入**，用 Safari 直接開就會跑。

> Pages 一定要走 HTTPS 才會生效：地理位置、Service Worker、以及
> 「加入主畫面」的全螢幕模式都需要安全來源（`https://` 或 `localhost`）。

## 加到主畫面

在 Safari 打開網址後：

1. 按下方工具列的**分享**鍵
2. 往下捲，選 **加入主畫面**
3. 按**新增**

之後點桌面上的圖示，就會**全螢幕**打開（沒有網址列、沒有分頁列），
而且一開啟就自動開始量測，不用再按任何按鈕。

## 本機預覽

```bash
cd docs && python3 -m http.server 8000
# 然後開 http://localhost:8000
```

Service Worker 在 `localhost` 也算安全來源，所以離線快取一樣可以測試。

## 檔案

| 檔案 | 用途 |
|---|---|
| `index.html` | 整個 App，CSS 與 JS 都內嵌，沒有外部相依 |
| `manifest.webmanifest` | PWA 設定：名稱、圖示、`display: standalone` |
| `sw.js` | Service Worker，快取 App 外殼；量測請求一律不快取 |
| `icon.svg` / `icon-*.png` | 圖示；`icon-180.png` 是 iOS 主畫面用的尺寸 |

## 量測方式

**延遲**：對各地區的 AWS S3 端點（`s3.<region>.amazonaws.com`）發出
`mode: "no-cors"` 的請求並計時。這些端點固定在該地區的機房，所以往返時間
真的反映到那個國家的距離；用 anycast 的主機則永遠只會回答你最近的節點，
量不出差別。每個地區先做一次暖身（DNS 與 TLS），再取三次的最小值。

**速度**：先下載 2 MB，若判定線路夠快再下載 20 MB，並從**首個位元組抵達後**
開始計時，把連線建立的成本排除在外。

**建議**：

```
可容忍延遲 = 10 ms + min(下載速度, 100 Mbps) × 0.8
```

延遲在「最佳值 + 可容忍延遲」以內的國家都標為可用。
線路慢的時候這個窗口很窄（1 Mbps 大約只有 11 ms），所以只有最近的節點可選；
線路快的時候窗口寬（100 Mbps 大約 90 ms），你就可以照自己想要的出口國家挑。
