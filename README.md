# ⚔ 方塊劍鬥 · Blocky Blade Duel

藍牙對戰的 3D 方塊劍鬥遊戲。完整的人形骨架、從頭盔到靴子的全套裝備，
還有一個會**學你打法**的超智能 NPC 讓你單機訓練。

純瀏覽器執行，**零外部相依**——沒有 Three.js、沒有打包工具、不用 npm install。
3D 渲染是自己寫的方塊光柵器，跑在一般的 2D canvas 上。

```
git clone <repo> && cd fake-minecraft-
python3 -m http.server 8080     # 或任何靜態伺服器
# 瀏覽器打開 http://localhost:8080
```

> 藍牙功能需要 **HTTPS 或 localhost**（瀏覽器的安全限制），單機訓練則沒有這個限制。

## 玩什麼

### 🤖 單機訓練 —— 跟超智能 NPC 對打

NPC 不是靠作弊變強的（它看到的世界跟你一樣，還帶反應延遲）。它強在會建模：

| 機制 | 做了什麼 |
|---|---|
| **感知延遲** | 透過延遲緩衝區看世界。新手 420ms、超智能 100ms，不會有讀指令的神反應。 |
| **對手建模** | 統計你的出招頻率、招式接續習慣（n-gram）、出手距離、格擋率、進攻節奏。 |
| **威脅評估** | 推算你這一刀什麼時候到、有多痛，才決定要招架、翻滾、搶攻還是拉開。 |
| **效用決策** | 對每個候選動作做一層 rollout：預期傷害 ×（1 − 你會擋的機率）− 被反擊的風險。 |
| **心理戰** | 你太愛舉盾就用假動作騙你、用盾擊破防；體力不夠就先拉開回氣。 |
| **自適應** | 落後時自動加壓並縮短反應時間，領先時收斂，避免一面倒。 |

打法性格分「進攻 / 均衡 / 防守 / 技巧」，血量落後 30% 以上它會自己換打法。

遊戲中右上角的 **NPC 思考面板** 會即時顯示它現在的意圖、威脅評估、
對你下一招的預測與信心度——你可以直接看到自己被讀死的過程。

### 📶 藍牙 / 連線對戰

三種管道，遊戲邏輯完全一樣：

| 管道 | 說明 |
|---|---|
| **藍牙 BLE** | Web Bluetooth + Nordic UART Service。**需要一顆 BLE 中繼**，見下方說明。 |
| **同網路直連** | WebRTC，不需要伺服器。房主產生邀請碼傳給對方，對方回傳回應碼即可。 |
| **同機雙分頁** | 同一台裝置開兩個分頁，一邊房主一邊挑戰者。適合先熟悉流程或兩人擠一台。 |

#### 關於藍牙的重要限制

**瀏覽器沒辦法把自己廣播成 BLE 周邊裝置**，只能當中央端（central）去連別人。
這是 Web Bluetooth 規格的限制，不是這個遊戲的問題——所以兩支手機的瀏覽器
無法直接用藍牙互連。

解法是放一顆便宜的 BLE 中繼在中間，兩邊都連上它：

```
  手機 A ──BLE──┐
                ├── ESP32 中繼（收到什麼就轉發什麼）
  手機 B ──BLE──┘
```

`tools/esp32-ble-relay/` 有現成的 Arduino 韌體，燒進任何一片 ESP32 就好，
不用寫任何程式。細節看那個資料夾裡的註解。

如果你手邊沒有 ESP32，用 **同網路直連（WebRTC）** 就能兩台裝置真人對戰，
一樣不需要伺服器。

## 操作

| 鍵 | 動作 |
|---|---|
| `W` `A` `S` `D` | 移動（相對鏡頭） |
| 滑鼠左鍵 / `J` | 右橫斬 |
| `Q` | 左橫斬（回掃，較快） |
| `E` | 上段劈（重、慢、破防高） |
| `F` | 突刺（最遠、最快） |
| 滑鼠右鍵 / `K` | 格擋（按住） |
| `R` | 盾擊（破對手格擋） |
| `Shift` | 翻滾（有無敵時間） |
| 空白鍵 | 跳躍 |
| `Esc` | 暫停 |

手機上有虛擬搖桿與六顆按鍵，介面會自動切換。

### 戰鬥規則

- **完美招架**：在對手砍中你的前 0.2 秒才舉盾，完全免傷並把他彈開，接著是免費的反擊機會。
- **體力**：攻擊、格擋、翻滾都吃體力。被打光會直接破防，那一下傷害 ×1.35。
- **部位傷害**：頭 ×2.0、軀幹 ×1.0、腿 ×0.75、手臂 ×0.65。護甲是**分部位**計算的。
- **裝備耐久**：護甲被打會慢慢碎，碎掉那個部位就沒保護了，而且模型上會直接脫落。
- **重量**：全套獄髓很耐打但移動與出招都變慢；輕裝靠翻滾與突刺一樣能贏。
- **假動作**：攻擊在蓄力階段可以取消，用來騙對方的格擋。

## 肢體與裝備

角色是 15 根骨頭的完整人形骨架，父子階層跟真的一樣：

```
hips ─┬─ torso ─┬─ head
      │         ├─ armRUpper ─ armRLower ─ handR ─ 武器
      │         └─ armLUpper ─ armLLower ─ handL ─ 盾牌
      ├─ legRUpper ─ legRLower ─ footR
      └─ legLUpper ─ legLLower ─ footL
```

同一份骨架同時餵給三個系統：渲染（方塊）、命中判定（6 個受擊膠囊）、
以及劍刃的掃掠線段。所以你看到的姿勢**就是**判定用的姿勢——
手臂真的伸到哪裡，判定就到哪裡。

**裝備欄位**（每一件都能單獨換材質，會實際穿在對應骨頭上）：

頭盔 · 胸甲 · 護肩 · 護臂 · 手甲 · 腰甲 · 護腿 · 靴子 · 主手武器 · 副手 · 披風

**材質**：布衣 / 皮革 / 鎖子甲 / 鐵 / 黃金 / 鑽石 / 獄髓
**武器**：匕首 / 鐵劍 / 長劍 / 巨劍 / 細劍 / 獄髓劍（刃長、重量、招式組都不同）
**副手**：空手 / 小圓盾 / 鳶盾 / 塔盾

裝備工坊裡改任何一件都會即時反映在攻擊力、防禦力、移動速度、出招速度與總重量上。

## 專案結構

```
index.html            介面骨架
style.css             UI 樣式（含手機版）
src/
  main.js             進入點：輸入、選單、遊戲迴圈
  core/
    math.js           向量 / 4x4 矩陣 / 線段最短距離 / 決定性亂數
    renderer.js       方塊光柵器：投影、近平面裁剪、畫家演算法、面法線打光
  game/
    rig.js            人形骨架、裝備穿戴、受擊膠囊、劍刃線段
    animation.js      關鍵影格招式 + 程序化走路 / 待機
    equipment.js      材質、護甲欄位、武器、套裝資料
    combat.js         招式時序、掃掠命中判定、傷害 / 格擋 / 招架結算
    fighter.js        戰士狀態機與物理
    ai.js             超智能 NPC
    match.js          回合流程、特效、運鏡
  net/
    protocol.js       二進位封包（塞得進 BLE 的 20 bytes MTU）
    transport.js      藍牙 / WebRTC / 同機分頁 / 本機迴圈
    netgame.js        房主權威同步 + 加入者本地預測
test/sim.test.mjs     30 項無畫面模擬測試
tools/esp32-ble-relay/  BLE 中繼韌體
```

### 網路設計

房主權威（host authoritative）：

- **房主**跑完整模擬，是唯一裁判。每秒送 20 次狀態快照。
- **加入者**本地也跑完整模擬讓自己的操作零延遲（本地預測），
  再依快照做誤差修正；對手的動作用快照插值播放。

封包全部量化過，狀態快照（兩名戰士的座標、朝向、血量、體力、狀態旗標、
當前招式與相位）壓在 **20 bytes** 內，剛好塞進 BLE 預設的 ATT MTU；
輸入封包只有 **4 bytes**。超過 MTU 的訊息（例如配裝同步）會自動分片重組。

## 測試

```bash
npm test          # 或 node test/sim.test.mjs
```

30 項無畫面測試，不需要瀏覽器就能跑完整個戰鬥核心：

- 骨架：所有骨頭矩陣有效、站立時腳底貼地、六個受擊部位分離、刃長正確
- 戰鬥：正面揮擊命中、距離外揮空、一招只判定一次、部位傷害倍率、
  護甲減傷、格擋 / 完美招架、背後攻擊擋不住、翻滾無敵、體力限制、假動作視窗
- AI：輸出合法輸入、會主動進攻、高難度贏過低難度、學得到出招習慣、
  感知延遲確實存在、五種難度都不會崩
- 回合：三戰兩勝正常結束、回合間正確重置
- 連線：輸入 / 狀態 / 事件 / 配裝封包來回一致、狀態封包 ≤ 20 bytes、分片重組正確
